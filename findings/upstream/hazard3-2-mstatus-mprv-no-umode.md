# mstatus.MPRV is writable when U_MODE = 0

## Expected behaviour

Privileged spec, mstatus: "If U-mode is not supported, MPRV is read-only 0."
With `U_MODE = 0`, `csrs mstatus, t1` with t1 = 0x20000 should leave MPRV at 0,
and mstatus should read back with bit 17 clear. The RISC-V Sail model,
configured without U-mode, masks the bit on write.

## Observed behaviour

MPRV is set and reads back as 1: after the `csrs`, mstatus reads `0x00021800`.
The bit is not inert; `hazard3_csr.v` derives the effective load/store
privilege from it.

## Platform

CXXRTL testbench `test/sim/tb_cxxrtl`, configuration `config_nou_noxh3irq.vh`
(the default configuration with `U_MODE = 0` and `EXTENSION_XH3IRQ = 0`,
attached), Hazard3 v1.1.1 (`8af99293`). The same write is present on
`develop` (`ba0c83c6`, `hdl/hazard3_csr.v:241`).

## Files

`config_nou_noxh3irq.vh` (place in `test/sim/tb_common/hdl/`),
`mstatus_mprv_no_umode.bin` (96 bytes, loaded at 0x80000000) and its listing
`mstatus_mprv_no_umode.lst`; generated by `mkrepro.py`, no ELF. The program
prints mstatus after the write and exits with the value of bit 17.

## Reproduce

```
cp config_nou_noxh3irq.vh test/sim/tb_common/hdl/
cd test/sim/tb_cxxrtl && make CONFIG=nou_noxh3irq
./tb-nou_noxh3irq --bin mstatus_mprv_no_umode.bin --cycles 2000 --logfile /dev/stdout --cpuret; echo "exit $?"
```

Output on v1.1.1:

```
00021800
CPU requested halt. Exit code 1
Ran for 13 cycles
exit 1
```

## How it was found

As a counterexample from a formal equivalence check of Hazard3 against the
RISC-V Sail model. In the mstatus write arm the neighbouring U-mode-only
fields (MPP, TW) are conditioned on `U_MODE`; MPRV is not.
