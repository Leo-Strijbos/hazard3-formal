# C.ADDI4SPN with nzuimm = 0 executes as `addi rd', sp, 0` instead of raising illegal-instruction

## Expected behaviour

The C extension defines `C.ADDI4SPN` with `nzuimm = instr[12:5]`, and states that the
code points with `nzuimm = 0` are reserved. The RISC-V Sail model raises an
illegal-instruction exception for all of them. Of the 16-bit encodings
`0x0000, 0x0004, 0x0008, ..., 0x001c` (bits 12:5 zero, bits 4:2 = rd'), all eight
should trap.

## Observed behaviour

Only `0x0000` traps. The other seven (`0x0004` through `0x001c`, rd' = x9 to x15)
retire as `addi rd', sp, 0` and the PC advances by 2.

With sp = 0xdead0000 and x10 = 0, executing the halfword `0x0008` leaves
x10 = 0xdead0000 and takes no trap.

## Platform

CXXRTL testbench `test/sim/tb_cxxrtl`, default configuration, Hazard3 v1.1.1
(`8af99293`, branch `stable`). The same decode is present on `develop`
(`ba0c83c6`, `hdl/hazard3_instr_decompress.v:208`).

## Files

`c_addi4spn_reserved.bin` (92 bytes, loaded at 0x80000000) and its listing
`c_addi4spn_reserved.lst`. The binary is generated by `mkrepro.py` from
hand-encoded instructions, so there is no ELF; the listing shows every word.
The program prints x10 after the reserved halfword, then exits with code 1.
If the halfword traps, the trap handler at MTVEC_INIT prints mcause and mepc
and exits with code 0.

## Reproduce

```
cd test/sim/tb_cxxrtl && make
./tb --bin c_addi4spn_reserved.bin --cycles 2000 --logfile /dev/stdout --cpuret; echo "exit $?"
```

Output on v1.1.1:

```
dead0000
CPU requested halt. Exit code 1
Ran for 13 cycles
exit 1
```

## How it was found

As a counterexample from a formal equivalence check of Hazard3 against the
RISC-V Sail model. The decompressor's reserved-encoding test for this case
is `~|instr_in[12:2]`, so it also requires rd' = 0 and only matches `0x0000`.
No compiler emits these encodings, so the practical impact is forward
compatibility: a future extension that allocates them would execute as an
`addi` here rather than trapping.
